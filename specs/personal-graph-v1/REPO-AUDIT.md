# Culture Atlas personal-graph build: integration audit

Audited October 27, 2026 against main `fb8a10ad774cd9135f284f96531b19ef08fc029e` and PR #7 head `7188184d8ec8b7482652799d97608351188c377a`. Read-only source inspection; no tests, deployments, or provider calls were run. The two source trees were compared by blob SHA for the relevant paths. PR #7 remains separate from main.

## Reusable foundation and required changes

| Concern | Existing source contract | Graph build implication |
| --- | --- | --- |
| Private ownership | `principal.ts` supplies account/session owner types, owner predicates, and distinct account/agent/installation/system principals | Private graph records need the same explicit owner pair or an account-only contract; shared nodes do not authorize private connecting edges |
| Agent grants | `authz/index.ts`, `library/access.ts` enforce current collection grants and require collection context for limited taste reads | Derived personal edges and recommendation proofs must be computed from granted support, not a global summary with fields removed afterward |
| REST/MCP parity | `schemas/routes.ts`, `authz/operations.ts`, `agent-gateway/src/server.ts` share route policies and per-request token resolution | Add typed route/tool contracts and parity tests; do not expose Graphiti's own server as the authorization boundary |
| Native clients | Raw installations are denied by `authorizeOperation`, but `authz/native-owner.ts` bridges an explicit v1 allowlist to account-owner authority | Preserve existing native onboarding/picks/feed/collection/capture-read bridge; new graph operations need an explicit bridge or v2 native policy |
| Jobs | DB queue has dedupe, leases, heartbeats, retries, cancellation, and publication checks | Reuse queue and staged outputs; add graph job types/payload validation/handler entries and revision-aware publication fencing |
| Growth | `interest_expand` already walks Qloo feed cards in bounded waves | Treat existing results as discovery-frontier candidates, never new evidence of user preference |
| Privacy deletion | Capture deletion removes private dependencies, cancels jobs, clears dedupe keys, removes media, and rebuilds taste | Extend this same transaction/dependency model to graph support, frontier, proofs, embeddings, and external projections |
| Spend | Compiler request budgets and model-gateway durable reservations already exist | Graph/embedding/research calls must use existing budget accounting, including retries and unknown-cost reservations |

## Authorization and public contracts

Ownership failures are 404, missing scopes are 403. Selected-collection agents must request `collection_id` for taste; global taste requires whole-library authority. Membership and derived context are checked against the current grant. Existing regression tests specifically prevent a reason from revealing an ungranted capture, and prevent duplicate-photo reuse from exposing a result outside a grant. Carry those guarantees into graph traversal, embeddings, evidence paths, cache keys, job reuse, and explanation text. [Privacy regressions](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/agent-privacy.test.ts)

The MCP server ignores browser cookies, resolves the bearer and current grant for each request, advertises only permitted tools, and authorizes calls against mirrored REST contracts. Existing `taste:read` means an explicit interest summary; `taste:write` means explicit save/unsave/hide actions. A broad new inferred-memory API should not silently inherit those meanings. Either restrict v1 to compatibility summaries or add explicit additive operations/scopes with new consent when authority expands. [MCP server](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/agent-gateway/src/server.ts), [route definitions](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/schemas/routes.ts), [scope descriptions](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/agent-gateway/src/contract.ts).

Native detail: `authz/native-owner.ts` already allowlists v1 onboarding, taste-pick edits, discoveries, item detail, related discovery, selected collection operations, and compiled capture reads. It checks token expiry, live installation/authority state, and `X-Atlas-Expected-Account` for mutations, then creates an account principal. It does **not** imply all v1 taste/preferences routes are available: main's allowlist does not contain `GET /v1/taste` or `POST /v1/preferences`. New `/v2/me/interest-graph` read/suppression operations can remain first-party-only with explicit account/installation policy and no MCP exposure initially. The existing ordinary-preferences seam is `apps/web/app/v2/me/preferences/route.ts` → `agentRoute` → `schemas/agent-routes.ts` → `services/agent-platform.ts`; it carries `If-Match` versioning but its existence does not establish native authority for a new route. [Native owner bridge](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/authz/native-owner.ts), [v2 preference handler](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/apps/web/app/v2/me/preferences/route.ts), [v2 route contracts](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/schemas/agent-routes.ts).

`services/jobs.ts` checks a job result against the current grant. New graph result types must extend that check; a creator's old permission cannot authorize future polling or result retrieval. Agent narrowing/rotation advances `authorization_version`; graph caches and queued agent work should use and revalidate it. [Jobs visibility](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/jobs.ts), [agent narrowing](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/agent-platform.ts).

## Queue, outbox, and continuous growth

`enqueueJob` accepts a transaction-compatible `Queryable`, validates typed payloads, and reuses nonfailed/noncancelled dedupe keys, including completed jobs. Failed/cancelled jobs release that reuse constraint. Handlers must stage provider calls with `runStage`, respect the abort signal and budgets, and call `ensureActive` before publishing. A graph job dedupe key should include owner, scope/grant context, input taste revision, graph/policy version, and refresh wave where needed. A revision check is additional to lease checks: a still-live worker can hold obsolete preference inputs. [Queue](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/jobs/queue.ts), [handler contract](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/jobs/handler.ts), [dedupe functions](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/jobs/dedupe.ts).

The repo already has a **specific identity authority outbox**, `identity_authority_events`, written by `endAuthority` in the same revocation transaction. It is not a generic preference graph event bus. For SQL-only graph work, enqueue the graph job in the preference transaction or introduce a purpose-specific graph outbox when projecting to another store. Do not repurpose identity events with unrelated meanings. [Identity migration](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/db/migrations/080_account_identity.sql), [authority lifecycle](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/native-sessions.ts).

The existing `interest_expand` service limits each attempt to four Qloo requests, a 45-second deadline, at most three attempts, and one poll-triggered wave per 15 minutes. Refresh uses minute-wave dedupe. Its pipeline prefers signals from recommendation cards already in the latest seed pool, falling back to explicit seed signals. This is deliberately discovery expansion; it must not become preference support merely because a card was fetched. Preserve the lineage back to explicit user roots and bound traversal depth; a recommendation chain can otherwise drift indefinitely. [Expand service](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/interest-expand.ts), [expand pipeline](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/pipeline/interest-expand.ts).

Required queue seams: `enums.ts` job types; `jobs/types.ts` payload schema; `jobs/dedupe.ts`; `pipeline/index.ts` handler registry; new pipeline modules; service enqueue points; worker scheduling/configuration. Existing per-attempt bounds are not automatically a global daily graph-research cap. Add account/day and global enforcement and keep foreground analysis capacity reserved. [Job types](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/enums.ts), [handler registry](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/pipeline/index.ts).

## Deletion and migration traps

Capture deletion takes the capture row lock, cancels active producers, clears dedupe keys, removes dependent private records, then deletes media after commit and rebuilds taste. Hourly purge physically deletes expired capture records and expired anonymous session data. Graph data needs both immediate read suppression and durable physical cleanup; an eventually consistent external graph must not continue serving a deleted observation. Independently supported canonical saves and shared public facts may survive, without private associations. [Capture deletion](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/captures.ts#L704), [purge worker](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/pipeline/purge.ts).

`docs/privacy.md` still marks account deletion end-to-end confirmation as TODO. The inspected account services and route contract expose creation/sign-in/sign-out rather than an account-delete API. Do not claim existing SQL cascades establish a complete account deletion workflow. Treat graph-aware account deletion/export/reset integration as an explicit build deliverable or release dependency, and verify all media namespaces and external projections. [Privacy limitations](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/docs/privacy.md), [account services](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/accounts.ts).

`claimSession` merges anonymous canonical duplicates, transfers saves/hides/captures/events/jobs/traces, invalidates session feed snapshots, advances account taste revision, and rebuilds taste. Add graph transfer/reprojection to this explicit table list if graph supports anonymous owners; otherwise defer graph materialization until account claim and backfill from current state. Never leave private anonymous graph nodes unclaimed or duplicate the same interest after merging. [Session claiming](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/services/accounts.ts#L61).

Model gateway spend reservations persist across workers; unknown or stale costs are retained rather than released automatically. New research/extraction/embedding calls need an eligible model role/profile and durable ledger identity, not a direct framework-provider shortcut. [Model spend contract](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/providers/src/model-gateway/budget.ts), [compiler request budgets](https://github.com/Vontarius-Ventures/culture-atlas/blob/fb8a10ad774cd9135f284f96531b19ef08fc029e/packages/domain/src/compiler/budget.ts).

## Main versus PR #7

The core auth index/operation policy, principal types, library access, job queue/handler/dedupe, purge worker, account services, and interest-expand service/pipeline have identical blob SHAs in the inspected main and PR trees. PR #7 changes `authz/native-owner.ts`, `jobs/types.ts`, `services/captures.ts`, and `agent-gateway/src/contract.ts`, among other style implementation files. Rebase and review those seams before implementation; do not overwrite PR-only style DTOs or native policy additions. Main can support the personal preference graph foundation independently; consuming PR-only observations/product evidence requires an explicit adapter and dependency decision.

Minimum regression suite: scoped REST/MCP parity; source-support filtering on explanations; revocation during a queued job; owner/grant-aware dedupe; stale taste publication fence; delete during a leased job; account/session claim; unknown-spend retention; frontier results never changing confirmed interests. Source inspection alone does not establish that these new contracts pass.
